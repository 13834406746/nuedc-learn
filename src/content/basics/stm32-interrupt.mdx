中断是单片机「同时处理多件事」的唯一方式：主循环在干活，串口来数据了、定时器到点了、引脚电平变了——都需要打断当前工作去处理。电赛代码里，中断的用法几乎决定了系统的实时性。

## 中断怎么工作的

一个中断事件（串口收到字节、定时器计数溢出、按键按下）会经过：

1. **外设置中断标志位**：硬件把事件记录在状态寄存器里
2. **NVIC 仲裁**：多个中断同时来，谁先执行？由 NVIC（嵌套向量中断控制器）按优先级决定
3. **CPU 跳转中断服务函数（ISR）**：保存现场，执行你的处理代码
4. **返回**：恢复现场，继续被打断前的工作

`stm32f10x_it.c` 文件里就是各种 ISR 的壳子，你在里面填自己的处理逻辑。

## NVIC 优先级：中断的调度规则

STM32F1 的优先级分两组：**抢占优先级**（preemption）和**子优先级**（sub）。

```c
/* 抢占优先级 1 级，子优先级 2 级（每组 2 位） */
NVIC_PriorityGroupConfig(NVIC_PriorityGroup_2);
```

- **抢占优先级**：谁高谁先执行，还能打断正在执行的低抢占中断（嵌套）
- **子优先级**：抢占优先级相同时才比较，不能嵌套，只能排队

电赛的实用分配原则：

| 中断 | 建议抢占优先级 | 理由 |
|------|----------------|------|
| SysTick 定时器（控制周期） | 最高（0） | 控制周期乱了一切全乱 |
| 编码器计数 | 高（0~1） | 丢脉冲 = 测速错 |
| 串口（通信） | 中（1） | 收太快会丢，但不能打断控制 |
| 按键/其他 | 低（2） | 慢事件不着急 |

**不要把中断优先级当成一回事**——配置错会导致诡异现象：控制周期被串口打断导致 PID 周期抖动（还记得 PID 对周期敏感的坑吗）。

## EXTI 外部中断

按键、循迹灰度传感器的数字输出，常用 EXTI：

```c
void EXTI_Init(void)
{
    EXTI_InitTypeDef e;
    e.EXTI_Line = EXTI_Line0;          /* 引脚 0 */
    e.EXTI_Mode = EXTI_Mode_Interrupt;
    e.EXTI_Trigger = EXTI_Trigger_Rising;  /* 上升沿触发 */
    e.EXTI_LineCmd = ENABLE;
    EXTI_Init(&e);
}

void EXTI0_IRQHandler(void)            /* 中断服务函数 */
{
    if (EXTI_GetITStatus(EXTI_Line0)) {
        /* 处理按键事件 */
        EXTI_ClearITPendingBit(EXTI_Line0);   /* 清标志！ */
    }
}
```

**清标志位是必须的**——不清的话中断会立刻再次触发，表现为「进了一次中断就死在里面」或反复执行。

## 中断服务函数里绝不能做的事

这是电赛最常踩的雷：

- **不要延时**：`delay_ms()` 在 ISR 里跑，等于整个系统停摆。ISR 里只做「快进快出」的事：置标志、搬数据。
- **不要做复杂运算**：浮点运算、大循环会拖长中断，影响其他中断和控制周期。
- **不要打印调试**：printf 在 ISR 里是灾难（重入、阻塞）。
- **正确姿势**：ISR 里置一个标志位（`volatile`），主循环检测到标志再慢慢处理。本站串口篇的 ringbuf 就是这么设计的——ISR 只负责搬字节。

## 常见坑

- **忘记清中断标志**：EXTI、USART 的 IDLE、定时器更新，不清标志中断就反复触发或卡死。
- **优先级分组不一致**：`NVIC_PriorityGroupConfig` 全工程只调一次（main 开头），多处调用会覆盖，中断行为变得不可预测。
- **ISR 里用非 volatile 全局变量**：主循环读到的是旧值。见 C 语言篇的 volatile 说明。
- **两个中断共享资源**：比如主循环和串口 ISR 都操作同一个缓冲区，要保证同一时刻只有一方在写（环形缓冲的 head/tail 设计就是为了免锁，见串口进阶篇）。
